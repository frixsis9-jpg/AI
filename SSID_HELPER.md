# Получение SSID через PocketOptionSSID.exe

`PocketOptionSSID.exe` находится в корне репозитория рядом с `main.py`.
Это отдельная программа для Windows 10/11 x64. Python, Playwright и установка
дополнительных пакетов не нужны. Нужен установленный Microsoft Edge или Chrome.

1. Скачайте обновлённый проект с GitHub и распакуйте его. Можно отдельно открыть
   `PocketOptionSSID.exe` на GitHub и нажать Download raw file. Программа должна
   лежать в вашей рабочей папке бота рядом с `main.py` и рабочим `.env`.
2. В PowerShell этой папки остановите контейнер: `docker compose stop bot`.
3. Дважды нажмите `PocketOptionSSID.exe`. Права администратора не нужны.
4. В открывшемся отдельном окне браузера войдите в свой Pocket Option вручную:
   пароль и при необходимости капча/2FA вводятся вами на сайте.
5. Откройте торговую платформу нужного аккаунта (демо или реального).
   Если сообщение авторизации не поймано, обновите торговую страницу.
6. Когда программа сообщит, что SSID найден, вернитесь в её окно, введите
   английскую `Y` и нажмите Enter. Без подтверждения файл не меняется.
7. После сообщения об успешном сохранении нажмите Enter для закрытия программы.
8. В PowerShell папки бота выполните:

```powershell
docker compose up -d --force-recreate bot
docker compose logs --tail 50 -f bot
```

Программа меняет только `POCKET_OPTION_SSID` в `.env`, остальные настройки
сохраняет. Рядом создаётся резервная копия `.env.ssid-backup-*`, которая тоже
содержит секреты: храните её локально. Новые резервные копии исключены из Git
и Docker-образа. Программа не перезапускает контейнер и не отправляет сообщения.

Используется временный отдельный профиль браузера, а не ваша обычная сессия
Edge/Chrome. Программа наблюдает исходящее сообщение авторизации только во
вкладках Pocket Option/po.trade своего окна; не читает сохранённые пароли,
не вводит логин и не обходит защиту входа. SSID не выводится в консоль и не
отправляется на сторонний сервер. После завершения окно закрывается и временный
профиль удаляется по возможности. Не используйте это окно для других сайтов.
Ожидание входа ограничено 15 минутами; закрытие окна отменяет получение.

SSID даёт доступ к аккаунту. Не публикуйте `.env`, резервные копии или SSID.
Получение свежего SSID не гарантирует доступность котировок. Если после обновления
бот всё ещё не получает тики, нужно отдельно проверить рынок/подключение.
В логах Telegram-прокси внутри Docker не должен указывать на `127.0.0.1`
Windows: для прокси на компьютере используется `host.docker.internal`.

## Сборка из исходников

Исходники находятся в `tools/ssid-helper`. Используется Go и закреплённая
зависимость `github.com/gorilla/websocket v1.5.3` с `go.sum`.

```powershell
cd tools/ssid-helper
go mod download
go test ./...
$env:GOOS="windows"
$env:GOARCH="amd64"
$env:CGO_ENABLED="0"
go build -trimpath -buildvcs=false -ldflags="-s -w" -o ../../PocketOptionSSID.exe .
```

Windows-бинарник собран в Linux. Автоматические проверки охватывают фильтрацию
кадров авторизации, ограничения доменов, изменение `.env`, резервирование и
повторное сохранение. Работа окна браузера и вход в реальный аккаунт на Windows
в облачной среде не проверялись. Файл не подписан сертификатом издателя.
