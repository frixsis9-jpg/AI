# Запуск на своём компьютере через Docker Desktop

Бот работает на вашем компьютере, пока компьютер включён, не спит и Docker
Desktop запущен. Python на Windows устанавливать не нужно. Используются Linux
containers. Порты открывать не нужно: бот сам подключается к Telegram.

## Сначала проверьте комплект файлов

Все необходимые папки теперь присутствуют: `ai`, `analysis`, `analyst`, `bot`,
`market_data`, `storage`. Используйте полную рабочую копию проекта вместе с
Docker-файлами. Содержимое анализа и остальных папок менять не нужно.

## Первый запуск (PowerShell в папке проекта)

1. Установите и запустите Docker Desktop с Linux containers.
2. Остановите старую копию бота (`stop_bot.bat` или её прежним способом).
   Для одного Telegram-токена должна работать только одна копия.
3. Оставьте свой рабочий `.env` рядом с `compose.yaml`. Если его нет,
   скопируйте `.env.example` в `.env` и заполните настройки локально.
   Нужны `TELEGRAM_BOT_TOKEN` и действующий `POCKET_OPTION_SSID`.
   Секреты не отправляйте в чат. `.env` подключается только при запуске,
   в образ не копируется; его формат читает сам бот, как при прежнем запуске.
4. Подготовьте папку базы. Если нужна прежняя статистика, копируйте базу
   **после полной остановки старого бота**. Существующую базу не перезаписывайте:

```powershell
New-Item -ItemType Directory -Force docker-data | Out-Null
if ((Test-Path signals.db) -and !(Test-Path docker-data/signals.db)) {
    Copy-Item signals.db docker-data/signals.db
}
docker compose up -d --build
docker compose logs --tail 100 -f bot
```

`Ctrl+C` завершает просмотр логов, бот продолжает работать. Новая статистика
сохраняется в `docker-data/signals.db` на компьютере и переживает пересборку
контейнера. Исходный `signals.db` остаётся без изменений. Каталог `docker-data`
сохраняйте и резервируйте; не добавляйте его и `.env` в Git.

После запуска откройте бота в Telegram, отправьте `/start` и проверьте
получение сигнала. Успешная сборка образа ещё не означает успешное подключение:
при просроченном SSID обновите его через `PocketOptionSSID.exe` по инструкции
в `SSID_HELPER.md`, затем пересоздайте контейнер указанной там командой.

## Дальнейшее управление

Контейнер `bot` появится в разделе Containers в Docker Desktop: там доступны
Start, Stop и Logs. Также можно использовать команды:

```powershell
docker compose stop
docker compose start
docker compose down
docker compose up -d --build
```

После изменения `.env` достаточно `docker compose restart bot`. После изменения
исходных файлов нужна пересборка: `docker compose up -d --build`.
`restart: unless-stopped` перезапускает бот после сбоев и запуска Docker Engine,
если контейнер не был остановлен вручную. Для старта после входа в Windows
включите запуск Docker Desktop при входе в его настройках.

Если `TELEGRAM_PROXY_URL` указывает на `127.0.0.1`, внутри контейнера это сам
контейнер. Для прокси на Windows используйте `host.docker.internal` вместо
`127.0.0.1`, сохранив схему и порт. Прокси должен разрешать подключения из Docker;
если он слушает только loopback Windows, потребуется настройка самого прокси.
Без прокси оставьте значение пустым, если Telegram доступен напрямую.

## Проверка в облачной среде

Проверка Compose прошла. Обычная сетевая сборка в облаке заблокирована DNS
внутри Docker. Для проверки зависимости скачаны с проверкой TLS снаружи
контейнера и установлен проверочный образ без сети: Python 3.11, зависимости,
импорт всех 39 модулей приложения и `main.py`, загрузка конфигурации с тестовыми
значениями, создание SQLite и повторное открытие базы прошли.
Это проверка зависимостей, а не подтверждение обычной сборки на вашем ПК.
Полноценная проверка сигналов требует действующих подключений к Telegram и
Pocket Option и выполняется на вашем компьютере после запуска. Старые
Windows-скрипты и логика бота этой настройкой не изменяются.
