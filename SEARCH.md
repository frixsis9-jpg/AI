# Поиск входов: ручная пара и автовыбор

Это первая экспериментальная версия отбора на основе существующей модели.
Файл весов `analysis/model_weights.json`, формулы индикаторов и структура
базового анализа сохранены. Новые проверки допуска не являются обученной
моделью вероятности; улучшение прибыльности не подтверждено бэктестом.
Стратегии из видео не добавлены. Бот не открывает сделки.

## Использование в Telegram

1. Откройте меню через `/start` или старые кнопки. После первого обновления
   заново выберите пару и экспирацию, если они были только в памяти старой версии.
2. Выберите **фиксированную экспирацию**: 5/10/15/30 секунд или прежние варианты
   от 1 минуты до 1 часа. Экспирацию выбирает пользователь; старый пункт
   «Авто — аналитик подберёт» больше не предлагается.
3. **Выбрать пару вручную**: поиск наблюдает только эту пару.
   **Автовыбор пары**: поиск сравнивает доступные пары из основного списка.
4. Выберите обычные пары, OTC или оба рынка. Через «Список пар» можно ограничить
   автовыбор. Пустой список означает все доступные основные пары.
5. Нажмите **Начать поиск**. **Проверить сейчас** делает один проход и, если есть
   подходящая ситуация, запускает такой же условный план входа.
6. **Статус поиска** показывает текущую причину ожидания. При отсутствии условий
   бот молчит, а не отправляет слабые сигналы каждые несколько секунд.
7. **Остановить поиск**, смена настроек и `/start` отменяют текущий поиск и его
   незавершённый план. На пользователя в чате действует одна задача.

Настройки сохраняются в той же SQLite-базе и переживают Docker restart.
Фоновые задачи после перезапуска **не возобновляются**: запустите поиск кнопкой.
Кнопки старых сообщений работают, повторять `/start` при каждом включении не нужно.

## Отбор и ограничение потоков

Используется реальный список активов от Pocket Option. Основной набор обычных
пар: EURUSD, GBPUSD, USDJPY, AUDUSD, USDCAD, USDCHF, NZDUSD. Дополнительно допустимы
AUDCAD, EURGBP, EURJPY, GBPJPY и доступные OTC-варианты этих символов.
Металлы и прочие шестибуквенные инструменты в автопоиск не включаются.
Ручное меню сохраняет список, который отдаёт провайдер.

По умолчанию одновременно открыты **не более двух потоков**. Группа наблюдения
меняется раз в 90 секунд; результаты сравниваются только в текущей группе,
а не объявляются лучшими на всём рынке. Если поток закреплён за планом или
незавершённой экспирацией, он не вытесняется. При занятых потоках поиск ждёт.
Частое переключение большого списка увеличивает прогрев и может уменьшать
число входов. Начните с двух-трёх пар.

Контроль перед каждым расчётом:

- UTC-время тика и время получения проверяются отдельно; смещения на +2 часа нет.
- Требуются 120 **полных непрерывных закрытых свечей на каждом из трёх TF**.
  Незавершённая первая live-свеча и неполные агрегаты не считаются полными.
- История запрашивается последовательно; если источник не отдаёт достаточную
  глубину (особенно H1), бот ждёт. Фиктивные свечи для заполнения дыр не создаются.
- Максимальный возраст тика: 0,5 с для 5/10 с, 1 с для 15/30 с, 2 с для 1–5 мин,
  5 с для более длинных экспираций. Это инженерные исходные пределы, не результат
  оптимизации на истории. Часы компьютера должны быть синхронизированы.

Секундный профиль использует S15/M1/M5, минутный до 5 минут — M1/M5/M15;
остальные прежние тройки сохранены. Направление определяет прежняя модель.
Последние тики и формирующаяся свеча выступают отдельными условиями допуска,
не прибавляются повторно к её вероятности. Требуются согласие хотя бы двух TF,
достаточный перевес, подтверждение движения, приемлемая волатильность и расстояние
до противоположного уровня. Запоздалый вход после большого ухода цены отбрасывается.
Пороговые значения находятся в `analysis/entry.py` и пока не калиброваны.

## Условное время входа

Предварительное уведомление приходит примерно за 20 секунд до целевого времени.
Время показано с датой в `Asia/Bishkek` (UTC+6). Выставьте такой же часовой пояс
на платформе либо измените `SEARCH_TIMEZONE` на её IANA timezone.

За 3 секунды до входа заново проверяются данные, направление и цена. При
противоречии, уходе цены более чем на 0,5 ATR или опоздании план отменяется.
Подтверждение должно завершить Telegram API-запрос до входа минимум за 0,5 с;
дополнительно ограничено время API-запроса относительно экспирации.

Это **не прогноз будущей цены на назначенную секунду**: время планируется после
обнаружения подходящих условий и остаётся условным. Telegram API не измеряет,
когда вы прочитали сообщение. Сетевые/клиентские задержки и ручное нажатие остаются.
Особенно для 5/10 с проверяйте возможность входа на демо; точность и прибыльность
этого режима не подтверждены. При позднем получении или пропуске времени не входите.

## Статистика и диагностика

В `signals` записываются только модельные входы, для которых есть достоверный
тик на целевое время, с версией `entry-v1`. Экспирация отсчитывается от этого
времени, а не от предварительного сообщения. Цена ручной сделки неизвестна боту.

Выход определяется по близким к целевому времени тикам. При отсутствии подходящего
тика используется UNKNOWN; более поздняя текущая цена для `entry-v1` не подставляется.
После перезапуска утраченную историю тиков бот не восстанавливает выдуманными исходами.
`/stats` разделяет пары, OTC-символы, экспирации и версии анализа. Балл качества
не выдаётся за процент побед; прежняя калибровка не смешивается с новым отбором.
В `search_events` сохраняются начала поиска, планы, отмены и факты модельного входа.

Опциональные настройки в локальном `.env` (добавлять необязательно):

```dotenv
SEARCH_INTERVAL_SECONDS=5
SEARCH_LEAD_SECONDS=20
SEARCH_MAX_FEEDS=2
SEARCH_TIMEZONE=Asia/Bishkek
```

Больший лимит потоков не гарантирует, что брокер его поддержит. При ошибках
подписок оставьте 1–2. Логи смотрите в Docker Desktop или командой:

```powershell
docker compose logs --since 5m bot
```

## Обновление существующей Windows-копии

Файл `update_bot.ps1` обновляет только перечисленные в манифесте файлы исходников
и документацию. Сначала скачивает и проверяет SHA-256 всех файлов одного коммита,
затем останавливает контейнер, сохраняет резервные копии заменяемых файлов и
локальной базы, копирует обновление и запускает пересборку. `.env`, SSID,
`analysis/model_weights.json` и существующий `signals.db` не скачиваются с GitHub.
При ошибке копирования/сборки возвращает исходные файлы; данные не удаляет.

Скачайте `update_bot.ps1` из репозитория в свою папку `AI-main` рядом с compose.yaml
и запустите из PowerShell этой папки:

```powershell
powershell -NoProfile -File .\update_bot.ps1
```

Скрипт не меняет системную политику выполнения PowerShell. Если она запрещает
запуск, используйте ручное обновление исходных файлов; исходники скрипта доступны
для проверки. В PowerShell на Linux проверены синтаксис, контроль хешей и откат при ошибке;
запуск на Windows здесь недоступен. После сборки проверьте логи и начните поиск через меню Telegram.
Старая копия бота вне Docker должна быть остановлена.

## Что проверено в разработке

Автоматические тесты используют синтетические котировки и подменённый Telegram:
свежесть/непрерывность, профили экспираций, отбор, смену направления и отмены,
одну задачу на пользователя, фиксацию целевого времени, SQLite и запуск/остановку
реального `main` без внешних сервисов. Проверочный Docker-образ использует Python
3.11 и те же зависимости из предварительно скачанных wheel-файлов: обычная сетевая
сборка в этой облачной машине блокируется DNS. Это не проверка реального SSID,
доставки Telegram на вашем ПК или торговой прибыльности. После обновления начните
с демо и двух пар; рабочие подключения проверяются по логам вашей копии.
